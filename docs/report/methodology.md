# IncidentIQ-Triage - Phase 2 methodology, provenance and limitations

All numbers quoted here are read from `results/*.json` (see [evaluation_tables.md](evaluation_tables.md), generated by `python -m incidentiq_ml.report_tables`). Real-data and synthetic-demo results are kept separate throughout.

## 1. Datasets and provenance

Access date for both downloads: 2026-11-21. Files are fetched by `python -m incidentiq_ml download` and verified against pinned SHA-256 values in `ml/src/incidentiq_ml/config.py`. Raw data is not committed.

| | Zenodo tickets | UCI incident event log | Synthetic generator |
| --- | --- | --- | --- |
| Source | https://doi.org/10.5281/zenodo.7648117 | https://doi.org/10.24432/C57S4H | `ml/src/incidentiq_ml/synthetic.py` |
| License | CC BY 4.0 | CC BY 4.0 | n/a (code in this repo) |
| Records | 2,229 tickets | 141,712 events, 24,918 incidents | configurable, seeded |
| Used for | Task A category (text) | Task B group (structured), Task C priority policy | demo of text/team models only |
| Target provenance | `category` as recorded in the source | first-event `assignment_group`; priority as recorded | labels **defined by the generator** |
| Status | REAL | REAL | SYNTHETIC (DEMO) |

The field registry in `config.py` records for every required field (incident_id, short_description, description, category, priority, assignment_group, created_at, service, impact, urgency) whether it is *observed*, *derived* or *synthetic* per dataset, and which are unavailable. No missing field is back-filled with invented values for real data.

**Leakage controls.** Resolution notes, closure fields, final reassignment history and other post-triage columns are listed in `config.UCI_LEAKAGE_COLUMNS` and dropped; only first-event (opening-time) values are used. A guard rejects any predictor that is the target or derived from it (tested in `ml/tests`). For UCI, the first-event group equals the final group for only 57.7% of incidents, so the target is the group at opening, not the eventual resolver.

## 2. Validation and EDA

`validation.py` checks schema, missing values, exact and near-duplicate text, class balance and text length (results in `results/validation_*.json`). `eda.py` produces the charts in `figures/` (class distributions, text length, incident volume over time, Cramer's V associations). The Zenodo tickets are highly templated and multilingual; 19-21% of test texts also appear in train under a random split.

## 3. Splitting and protocol

- Tickets: stratified **grouped** split; near-duplicate clusters (1,299 clusters, 1,035 rows in multi-row clusters) stay in one partition. 1,242 / 380 / 607.
- UCI: **chronological** 70/15/15 by `created_at` (16,808 / 3,602 / 3,602), because incidents are time dependent. Groups with fewer than 30 training incidents are bucketed as `OTHER (rare)` (1.3% of incidents); 906 rows with unknown first group are dropped.
- All preprocessing (TF-IDF, one-hot) is inside scikit-learn `Pipeline`/`ColumnTransformer` and fitted on training data only. Hyperparameters (C, word n-gram range, char n-grams on/off) are tuned on validation only; finalists are refit on train+validation and evaluated **once** on the test set. Test numbers are reported for every ablation cell, but the winner is chosen by validation macro-F1. Seed 42.
- Leakage diagnostic (tickets, fixed LogReg config): macro-F1 0.736 with the grouped split vs 0.781 with a naive random split, i.e. random splitting would overstate performance.

## 4. Tasks and models

- **A (category):** majority, keyword rules, TF-IDF + LogReg, TF-IDF + LinearSVC.
- **B (group):** majority, category-to-group map, keyword baseline (synthetic), LogReg and LinearSVC over feature-set ablations (text-only, structured-only, combined for synthetic; category / category+subcategory+symptom / context / impact+urgency / all for UCI). Top-k is reported only for models with valid scores; SVM margins rank classes but are never called probabilities. Majority and keyword baselines have no top-k.
- **C (priority):** priority is a deterministic function of impact x urgency (0 violations in 141,712 events). It is implemented as a policy (`policy.py`) and documented as such; the 1.0 macro-F1 and high-priority recall are by construction. The (impact=1, urgency=3) cell never occurs and is left undefined.

## 5. Explainability and calibration

- Per-prediction contributions: linear coefficient x TF-IDF value from an uncalibrated linear model with the same configuration; global top features per class; permutation importance for structured columns.
- SHAP/LIME were deliberately not added: for linear models the exact coefficient contributions are already the model's own explanation (rationale in `explain.py`).
- Confidence routing uses calibrated probabilities (sigmoid or isotonic, picked on validation ECE, calibration CV grouped by cluster/template). Deployed category model: test ECE 0.174, mean confidence below accuracy (underconfident); native LogReg probabilities had ECE 0.104, i.e. better on that metric. The threshold table in the evaluation tables is the practical routing evidence (for example confidence >= 0.7 covers about 66% of test with about 99% accuracy on covered items).

## 6. Artifacts and serving

`ml/artifacts/manifest.json` records library versions, configuration, class mapping, metrics, dataset fingerprint, split, text template, provenance, SHA-256 and model version for each joblib bundle. Two models are served: `category_real` (real tickets) and `team_synthetic` (synthetic demo, the app's five teams). Because the team model is synthetic, triage responses are labelled `DEMO`. The backend verifies path, SHA-256 and library versions before loading and never loads files outside `MODEL_DIR`; joblib files must be trusted.

## 7. Limitations

1. The tickets dataset is small, templated and multilingual; some classes have very few test examples (per-class F1 is noisy, one class has no test support), and category definitions are the source's, not this project's.
2. Near-duplicate grouping reduces but may not eliminate template leakage.
3. UCI has no free-text descriptions; Task B there uses structured fields only. Its target is the first group, which often differs from the final one.
4. Rare-group bucketing and dropping unknown groups change the label space.
5. Synthetic results (labels defined by the generator, with injected label noise) illustrate the pipeline only; ablation outcomes mirror the generator design, and they must not be cited as real-world accuracy.
6. No real combined dataset has text, structured fields and team labels together, so the end-to-end triage mixes a real category model with a synthetic team model.
7. Calibration of the category model is underconfident; probabilities should not be treated as exact.
8. Priority is a policy inherited from ServiceNow's impact x urgency matrix; no independent priority labels were available.
9. No human-in-the-loop evaluation or production latency study has been performed.
